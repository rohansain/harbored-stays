I intentionally chose a modular monolith architecture for Harbored. By decoupling our domain boundaries (Auth, Listings, Bookings, Payments) at the package and interface level rather than the network level, we eliminated distributed transaction overhead and network latency while maintaining a rapid development velocity. Because domain boundaries are strictly decoupled, extracting any service—such as Payments or Bookings—into an independent microservice using the Strangler Fig pattern requires zero database schema rewrites.
